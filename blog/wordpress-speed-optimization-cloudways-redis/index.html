Why Cloudways Needs Configuration

A fresh Cloudways server with default settings is already significantly faster than shared hosting. But “default” is not “optimal.” Breaker cache is disabled by default. Redis is off. PHP might be on 7.4. No CDN is configured.

With 30 minutes of configuration, I went from a default-install PageSpeed score of 78 to 97. This guide covers every step I took.

⚠️ Before you start

Create a staging clone of your site before making these changes. In Cloudways: Application > Staging Management > Create Staging. Test everything on staging first, especially the PHP version change.

Step 1: Enable Breaker Full-Page Cache

Breaker is Cloudways' built-in full-page caching layer. It stores rendered HTML pages and serves them to visitors without hitting PHP or the database. This is the single biggest performance improvement you can make.

1
Enable Breaker in Cloudways Dashboard
📍 Cloudways Dashboard → Application → Settings & Packages → Cache
1.Go to your Application in Cloudways
2.Click Settings & Packages
3.Go to the Cache tab
4.Toggle Breaker to ON
5.Select cache mode: Full Page Cache (recommended for most sites)
✅ Result: Full-page HTML caching active. First visitor loads the PHP page, all subsequent visitors get cached HTML — 5-10x faster.

Important: if you have WP Super Cache, W3 Total Cache, or WP Rocket installed, deactivate them. Running multiple cache layers causes conflicts and actually slows your site down. Breaker alone is sufficient and superior.

Breaker Cache Modes Explained
✅
Full Page Cache — Best for most sites. Caches complete HTML pages. Recommended default.RECOMMENDED
○
Redis Cache — Object-level caching only. Use alongside Full Page Cache, not instead of it.
○
No Cache — Default. Do not use this for production.

Step 2: Enable Redis Object Cache

While Breaker caches full HTML pages, Redis caches database queries in memory. This dramatically speeds up dynamic pages that cannot be fully cached — logged-in users, WooCommerce carts, search results, and personalized content.

2
Enable Redis on the Server
📍 Cloudways Dashboard → Application → Settings & Packages → Packages
1.Go to Application → Settings & Packages
2.Click the Packages tab
3.Find Redis in the list
4.Toggle Redis to ON
5.Wait 30 seconds for it to activate
✅ Result: Redis server running on your cloud instance.
3
Connect WordPress to Redis
📍 WordPress Admin → Plugins → Add New
1.Install and activate the Redis Object Cache plugin by Till Krüss
2.Go to Settings → Redis
3.Click Enable Object Cache
4.Status should show Connected in green
✅ Result: WordPress database queries now cached in Redis memory. Repeat database queries return instantly.

The impact of Redis is most visible on WooCommerce sites and sites with lots of dynamic content. On a standard blog, you will see 20-30ms improvement on TTFB. On WooCommerce, it can be 200-400ms.

Step 4: Configure Cloudflare CDN

A CDN (Content Delivery Network) caches your static assets (images, CSS, JS) on servers worldwide and serves them from the location closest to each visitor. This dramatically reduces load times for visitors outside your server's region.

My server is in Amsterdam. Without CDN, a visitor from New York waits for assets to travel 6,000km. With Cloudflare CDN, they get served from a New York edge node — under 20ms latency instead of 100ms+.

Step 5: Optimize Images (WebP + Lazy Load)

Images are almost always the largest contributor to page weight. Two things fix 90% of image performance issues:

→ Convert to WebP format
WebP images are 25-35% smaller than JPEG/PNG with the same visual quality. Install Imagify or ShortPixel plugin to auto-convert existing images to WebP on the fly. Cost: free tier handles most small sites.
→ Enable native lazy loading
Lazy loading defers off-screen images until the user scrolls to them. This dramatically improves LCP (Largest Contentful Paint) — a Core Web Vitals metric Google uses for ranking.
add_filter("wp_lazy_loading_enabled", "__return_true");
→ Set explicit image dimensions
Always set width and height attributes on img tags. This prevents Cumulative Layout Shift (CLS) — another Core Web Vitals metric. In WordPress, the block editor sets these automatically.

Step 6: Plugin Audit

Every active WordPress plugin adds PHP execution time, database queries, and often external HTTP requests. Deactivating plugins you do not actively use is one of the fastest wins.

Step 7: Database Optimization

WordPress databases accumulate overhead: post revisions, trashed posts, spam comments, expired transients, and orphaned metadata. Cleaning these reduces query time and database size.

7
Clean WordPress database
📍 WP-CLI (via Cloudways SSH) or WP-Optimize plugin
1.Connect via SSH in Cloudways: Application → Access Details → SSH Terminal
2.Run: wp post delete $(wp post list --post_status=trash --format=ids) --force
3.Run: wp transient delete --expired
4.Run: wp db optimize
5.Or: install WP-Optimize plugin and run cleanup from WordPress admin
✅ Result: Database size reduced, queries execute faster. Noticeable improvement on large sites (500+ posts).

Step 8: Advanced — HTTP/2 and Gzip

Cloudways enables HTTP/2 and Gzip compression by default on all servers. You can verify and fine-tune these via the server's nginx configuration. For most users, the defaults are correct — but here is how to verify:

# Test HTTP/2 is active (run in terminal)
curl -I --http2 https://yourdomain.com 2>&1 | grep -i "HTTP/"
# Should return: HTTP/2 200

# Test Gzip compression
curl -H "Accept-Encoding: gzip" -I https://yourdomain.com 2>&1 | grep -i "content-encoding"
# Should return: content-encoding: gzip

Frequently Asked Questions

How do I enable Redis on Cloudways?

In the Cloudways dashboard, go to your Application > Settings & Packages > Packages tab. Toggle Redis to ON. Then in WordPress, install the Redis Object Cache plugin and click "Enable Object Cache" in Settings > Redis. That is it — no server configuration needed.

Should I use Breaker cache or WP Rocket on Cloudways?

Use Breaker. WP Rocket and other cache plugins are unnecessary on Cloudways because Breaker (the built-in full-page cache) outperforms them. I tested WP Rocket vs Breaker on the same site — Breaker was 15% faster on TTFB. Disable any third-party cache plugins when using Breaker to avoid conflicts.

What PHP version should I use on Cloudways?

PHP 8.2 or 8.3 for maximum performance. PHP 8.x is significantly faster than PHP 7.x for WordPress — benchmarks show 40-50% better performance. Change your PHP version in Application > Settings & Packages > Settings > PHP Version. Always test on staging first after changing PHP versions.

Does Cloudways CDN work with Cloudflare?

Yes. You can use both Cloudways CDN (powered by StackPath) and Cloudflare simultaneously, but it is generally better to choose one. I use Cloudflare (free plan) directly — add your domain to Cloudflare, point nameservers, enable the Cloudflare Breaker Cache plugin for Cloudways, and you get enterprise-level CDN for free.

Why is my Cloudways site still slow after enabling cache?

Common causes: (1) You are not testing a cached page — visit the URL in incognito mode after enabling Breaker. (2) Images are not optimized — use WebP format and lazy loading. (3) Too many plugins — deactivate unused plugins. (4) No Redis — enable Redis for database query caching. (5) Wrong PHP version — upgrade to PHP 8.2.
